# Project Decisions

Decisions made, with the why — consult before re-litigating anything. One per line: decided X (not Y) because Z.

## Architecture

- Rasterization is a pluggable `IRasterizer` backend shipped as its own package (FreeType, StbTrueType, GDI, DirectWrite, Native), not a core dependency (Phases 30, 78): no single rasterizer covers every target — FreeType's native library is missing on browser-wasm, Linux arm64 and Mac Catalyst and fails to link on iOS, while BMFont pixel parity needs Windows GDI.
- The FreeType backend uses FreeTypeSharp (MIT, P/Invoke over native FreeType) and everything it exposes — metrics, glyph bitmaps, SDF, hinting, AA modes: industry-standard and the most complete feature set where its native library exists.
- TTF tables (GPOS/kern kerning pairs, OS/2, name strings, cmap coverage, variable-font axes) are parsed by our own pure C# parser in core, so kerning and metadata are identical whichever backend renders.
- Texture packing is MaxRects (BestShortSideFit) primary with Skyline as a fast mode: MaxRects packs ~93-97% efficiently, Skyline is 2-5× faster for 2-5% less efficiency. Own implementation from public-domain reference code.
- The API is in-memory-model-first with output methods on top (`.ToString()`, `.ToXml()`, `.ToBinary()`, `.ToFile()`), so the core pipeline stays format-agnostic and does zero disk I/O by default.
- MIT throughout, with no paid or split-license dependencies — SixLabors is explicitly excluded for its split license.
- FreeType memory is managed manually via `IDisposable`, pinning font data with `GCHandle`; do NOT use `FreeTypeFaceFacade`.
- Errors use a custom exception hierarchy rooted at `BmFontException`, so a consumer can catch everything this library throws with one clause.
- The desktop UI is MonoGame (DesktopGL) + GUM, code-only (no XAML, no GUM editor). Avalonia, WPF and MAUI were evaluated and rejected because MonoGame+GUM aligns with the game-developer audience. The original rationale also counted on KNI (an API-compatible MonoGame fork) for a cheap Blazor WebGL path later; re-check that assumption before relying on it, since the Gum integrations now live in Vic's repo.
- The StbTrueType backend gets an OTS-style structure check of its own (not a dependency on Native's parser, and not a fix in StbTrueTypeSharp, whose authors decline bounds checks) as defense in depth; the trusted-fonts-only wording stays, because the check bounds what stb reads, not every path in stb's rasterizer. Where a legal font would make stb read past its buffers the check repairs the backend's private copy rather than rejecting: a one-point off-curve last contour (Calibri, Consolas, SimSun, Malgun, Yu Gothic space glyphs) is made on-curve, which keeps its zero area; rejecting it would refuse common system fonts. Point-matched composite components are rejected, because stb does not consume their arguments and would read the rest of the record misaligned; only the `cmap` subtable stb selects is deep-checked, since rejecting a font for a subtable no code reads gains nothing.
- Cross-platform reach comes from the managed backends (StbTrueType, Native), not FreeType: they run wherever .NET runs, including browser-wasm, Linux arm64, iOS and Mac Catalyst.
- The StbTrueType backend is documented as **trusted fonts only**; untrusted input (uploads, user-supplied URLs, servers) is pointed at Native or FreeType. stb_truetype does no bounds checking of font data, its maintainers close such reports as won't-fix (it would need an API break), and in .NET an out-of-bounds pointer read is an uncatchable access violation that ends the process, so neither upstream nor a try/catch can make it safe.
- StbTrueType's `None` thin-stroke fix is dropout control from the outline in our wrapper (Native's rule over stb's own flattening), not a change to stb_truetype (third-party; we only pass it parameters), not oversampled coverage downsampled with a looser rule (cannot guarantee a stroke survives), and not a coverage heuristic (cannot tell a thin stroke from the gap between two strokes). Plain thresholding erased stems under half a pixel or split evenly over two (Roboto at a 12px cell: "The quick brown fox jumps" as "I ne quick brown fox umos").
- StbTrueType's `None` boxes are cropped to the ink, with `GetGlyphMetrics` rendering a `None` glyph to measure it (as Native does), not left at stb's outward-rounded box: after thresholding, 73 of 94 Roboto glyphs at a 12px cell carried an empty edge row or column and the boxes summed to 30% more area than Native's (3042 vs 2321 px²) — wasted atlas space, and offsets a pixel off the other backends'. The cost is a render per `None` `GetGlyphMetrics` call (`QueryAtlasSize`), accepted as it is on Native; `Grayscale` is untouched, byte for byte.
- Atlas PNGs are encoded by core's `PngEncoder` (filter type 0 on every row, one IDAT, BCL `ZLibStream` at `Optimal`), not StbImageWriteSharp: on atlas pages stb's per-row adaptive filters and own deflate were 3-6x slower and 16-42% larger (Roboto 32px ASCII page 1.85 ms → 0.50 ms; emoji and gradient pages included), and PNG encoding was most of a `ToFile` call. Adaptive filtering was measured and rejected — it compressed atlas pages worse than no filter. The cost: PNG bytes follow the runtime's zlib (.NET 9 moved to zlib-ng), so identical pixels can encode to different files on .NET 8 and 10; decoded pixels never differ.
- `EqualizeCellHeights` is BMFont's `useFixedHeight` (Jeremy's choice, #313): every cell spans the line box (`yoffset` 0, `height` = `lineHeight`, baseline at row `base`), grown for every cell when a glyph reaches outside it, not clipped and not the tighter tallest-glyph box it used to pad to; the cell is computed in `PreparedRasterization.RasterizeAndProcess` from the same line metrics the model writes, because packing needs the final heights.

## Native Rasterizer

- The Native rasterizer, and any core code it depends on, is pure managed C# we write — no P/Invoke, no native libraries, no new third-party packages (not "managed where convenient") — because its reason to exist is running on browser-wasm and iOS/NativeAOT with zero foreign code; a native or P/Invoke dependency reintroduces exactly the platform gaps FreeType has.
- Native LCD output is `Rgba32` with alpha = max(R, G, B), not mean: no channel exceeds alpha, so every pixel is a valid premultiplied colour, and a fully covered pixel is the same (255, 255, 255, 255) a grayscale glyph becomes on an RGBA page. Copying the FreeType backend's layout (3-bytes-per-pixel `Grayscale8`) was rejected — it stretches glyphs 3x in the atlas.
- `LcdFilter.Default` means "the backend's choice", and Native's choice is the one-pixel box ([1,1,1]/3, equivalent to three renders shifted by 1/3 px), not the 5-tap [1,2,3,2,1]/9: it is what the FreeType backend's LCD output measures as, so the two backends agree per channel and existing LCD output did not change when the options went public. The 5-tap kernel is public as `Smooth` (named for its effect; FreeType's `Legacy` names a different filter), and the enum names follow FreeType/fontconfig presets (`LcdSubpixelOrder` uses fontconfig's `rgba` names).
- LCD is never super sampled, and the rule lives in core (`PreparedRasterization.Prepare`), not in Native, so it covers the FreeType backend's `Lcd` too: box-filtering an N× render averages each channel across N subpixel strips and erases the pattern the mode exists for. A backend that degraded `Lcd` to grayscale still supersamples.
- The fix for integer-advance line drift (−18.5 to +11.3 px per 89 characters at text sizes, measured by the small-text exploration) is unrounded per-glyph metrics in the extended metadata (`FractionalMetrics`), not multi-phase atlases (several renderings per glyph at sub-pixel pen phases): two phases only cut the RMS gap error by about 30%, no stock renderer consumes a phase encoding, and the atlas would multiply. The metrics are opt-in rather than always on because the `kernsmith` block is written only when a field needs it, so a default font has no block at all and adding a line per glyph by default would change every `.fnt`; in 1/64 px, FreeType's 26.6 resolution, so a value is exact in decimal and in a float; and `lsb` is the ink's edge (the font's bearing), not an unrounded `xoffset`, because `xoffset` folds in padding, effect margins and SDF spread that a pen position must not — a renderer keeps placing the bitmap by `xoffset` and advances the pen by `advance`. The hinting deltas are reported separately (hinted − unhinted, only where the backend knows) instead of folding the hinted values into `advance`, so a renderer can choose the font's spacing or the spacing the hinted bitmaps were made for; `advance + advanceDelta` closes exactly to `xadvance` on FreeType, whose hinted advance is a whole pixel.
- The legibility score's topology family is three terms — the contrast-band term kept as it was (binary per glyph and cut, cuts 80/128/176), a graded topology-error term and a broken-ring term — weighted together at the 0.20 the band term carried alone (0.10/0.05/0.05), not a redefinition of the band term: at the read cut a lost feature is charged once between the two new terms by its cause (a ring open at 128 but whole at 64 is an ink-weight failure; a feature gone at every cut, or merged, a shape failure) and again by the band term, which also sees the outer cuts; keeping the band term binary and unchanged kept its margin reading and the sweep history comparable, and the family weight kept the ranking tests' orderings. `brokenRings` and `topologyError` partition the read-cut hole errors (`TopologyError` subtracts `BrokenRings`), so no counter is charged in both. The pairwise page's `fit_bt.py` features are reproduced strip-level (same lines, margin, band and gap rules), not re-expressed as per-glyph terms, so its fitted weights describe the numbers the tool prints; `--weights` maps a fit-form file onto the terms by the sign each term rewards and drops a contradicting feature with a note rather than negating it.
- Super-sampled advances and bearings round to the nearest output pixel, halves away from zero (`PreparedRasterization.DownscaleMetric`), although BMFont truncates them — legibility over BMFont parity here (Jeremy's call). Evidence: BMFont64 on Roboto at a 12px cell gives `aa=4` advances a pixel shorter than its `aa=1` ones on 27 of 95 glyphs and never longer (`floor(exact)` matches 87/95, `round(exact)` 65/95; `aa=2` 17 short, `aa=3` 22), and KernSmith's integer division did the same (Native 25 of 94 short: '#' 5.60 px → 22/4 = 5, 'B' 5.67 → 5, ',' 1.79 → 1; StbTrueType/DirectWrite 25, GDI 30, FreeType 29), which is why super-sampled text read cramped. Bearings round the same way instead of truncating toward zero: the ink then sits within half a pixel of its true position on either side, where truncation always pulled it toward the pen origin by up to a full pixel. Rounding an already-rounded high-res value is a two-step rounding, so an x4 advance can differ from the x1 one where the true advance is within 1/8 px of a half (Roboto 'T' 5.4 px: 5 at x1, 22/4 = 5.5 → 6 at x4; a sentence came out 179 vs 177 px); carrying an unrounded advance would put a float in `GlyphMetrics`, rejected for a 1/8 px case. Grid-aligning the downscale (padding the high-res bitmap so each block starts on an output pixel) would place ink exactly but change every super-sampled bitmap's size and the `QueryAtlasSize` model; not done.
- Unadvertised anti-alias modes degrade silently (`Light`/`Lcd` -> `Grayscale`) — no warning, no exception, no strict mode — because existing configs requesting `Light` on GDI/DirectWrite/StbTrueType must keep generating unchanged. Unadvertised hint levels degrade the same way (step down to the nearest listed level, else `Default`), for the same reason and so a config can name `full` once and render on every backend. The one hard failure is `EnableHinting = false` with an explicit hinted level (`ArgumentException`, CLI usage error): letting either side win silently would hide a contradiction the caller wrote, and no existing config combines them. FreeType and GDI advertise `Full` (their default hinted output) rather than only `None`, so `Full` on them stays hinted instead of stepping down to unhinted; DirectWrite advertises `Light` (`NATURAL_SYMMETRIC`) for the same reason.
- The FreeType backend's `Light` loads `FT_LOAD_TARGET_LIGHT` (Phase 188 Q3: fixed, not left as normal hinting under another name). FreeType's light hinting is a load-time target; setting only `FT_RENDER_MODE_LIGHT` at render time gave the coverage `NORMAL` gives, so `AntiAlias = Light` was byte-identical to `Grayscale` on the one published backend that advertised it. `HintLevel.Light` maps to the same target (so FreeType advertises `None`, `Light`, `Full`; `Normal` steps down to `Light`, no longer to `None`), an explicit `Full` keeps the default target even with `AntiAlias = Light`, and `EnableHinting = false` still loads `FT_LOAD_NO_HINTING` whatever the mode. The cost, accepted: FreeType's `antiAlias=light` + `useHinting=1` output changes (y-only fitting, linear advances — the `hint-*` harness configs on FreeType).
- Native (and `KernSmith.Imaging`) may not call libm — no `Math`/`MathF` `Pow/Exp/Log/Sin/Cos/Tan/Atan2/Acos/…` anywhere but `Internal/DeterministicMath.cs`, which rebuilds them from IEEE-exact operations — and may not use parallel loops or SIMD whose result depends on the vector width (one per-lane kernel is allowed, bit-pinned to its scalar loop), because "the same bytes on every host" is Native's reason to exist and those are exactly the operations that break it: libm rounds the last bit differently on Windows, glibc, Apple and Emscripten, a width-dependent or threaded reduction sums in a different order per machine. Rejected alternatives: trusting libm (it is within 1 ulp everywhere, but 1 ulp either side of a .5 is a different byte; it also hid behind JIT-time constant folding on the JIT host), per-platform goldens (would bless the drift instead of removing it), and `MathF`-everywhere (same libm problem). Precomputed tables are fine when built with `DeterministicMath`. A source scan test enforces the rule, and a cross-platform manifest proves the result rather than assuming it.
- Native's code is original — we write it from specs and general geometry/rasterization literature, and do not port third-party code into it, even under a compatible license (so synthetic bold is our own control-polygon offset, not a port of FreeType's `FT_Outline_EmboldenXY`): the goal is a 100%-our-code pipeline with nothing to attribute. Matching another backend's *output* (strength formulas, slant constants, placement) is fine; copying its implementation is not.
- Native SDF measures distance to the filled region's boundary under the non-zero rule — overlapping contours are clipped against each other first — not to the raw contours (as FreeType does): a hidden interior edge would otherwise put a ~128 seam through every glyph built from overlapping contours, which variable-font outlines routinely are.
- Native SDF measures to a polyline flattened with Wang's bound at spread/512 px (a quarter code value), not to the exact curves: the error is bounded and documented, the distance kernel stays a branch-light point-to-segment test, and it already matches FreeType within 2 code values while running 5-8x faster.
- Native SDF spread is `SdfSpread` rounded half away from zero with no upper clamp (FreeType clamps to 2..32), because the `.fnt` `sdfSpread` metadata uses that same rounding — the field decodes exactly from the metadata.
- Multi-channel fields are a `SdfMode { None, Sdf, Msdf, Mtsdf }` option next to the shipped `bool Sdf` (not a replacement): `EffectiveSdfMode` = `SdfMode` when set, else `Sdf`. `RasterOptions.FromGeneratorOptions` sets `RasterOptions.Sdf` exactly when the effective mode is single-channel, so backends that only read `Sdf` never mistake an MSDF request for SDF. `SupportsMsdf` is a default-false interface member, so no existing backend changes. This public API shape is accepted as is.
- Native MSDF's artifact correction checks every cell against the true single-channel distance field, which it computes as well; that extra cost (several times an SDF) is accepted because uncorrected fields show interpolation artifacts on ordinary glyphs.
- MSDF/MTSDF reject effects, fill color, channel packing, custom channel layouts, atlas variants and `ColorFont`, because each treats RGB as color (single-channel SDF + `ColorFont` stays allowed: COLR glyphs render in color and the rest as SDF, matching FreeType); `SdfScale` downsampling averages MSDF channels independently (not premultiplied), because MTSDF alpha is a distance, not opacity.
- MSDF `.fnt` output writes `alphaChnl=4` (alpha set to one) and `sdfMode=msdf|mtsdf` in the `kernsmith` line; single-channel SDF writes no `sdfMode`, so existing SDF output stays byte-identical.
- Native MSDF channel signs come from edge orientation and are then forced to agree with the non-zero rule (all channels negated when the median disagrees), not taken from winding per channel: per-channel winding would erase the pseudo-distance sign flips that make corners sharp.
- Native rounds the advance once (font units × scale, to the nearest pixel; `HintLevel.Normal` keeps that advance and places the fitted ink inside it), not FreeType's two-step 1/64-pixel rounding: the occasional one-pixel difference is accepted over mirroring FreeType's fixed-point pipeline. An exact half pixel rounds up (away from zero), as FreeType's does, not to even (Jeremy's choice): ties-to-even gave Roboto `D` at 16px (10.5 px) 10 where FreeType gives 11, a difference with no fixed-point excuse. The StbTrueType backend still rounds ties to even, so Native and stb differ there.
- A Native glyph box over 64 ems is a `RasterizationException`, accepted as the price of bounding allocation on damaged or hostile fonts.
- A `glyf` header box that misses a stored point by more than a unit, and the drawn outline too, is stale and replaced by the points' control box (FreeType's box), not used as given: a stale header clipped or shifted ink. Correct headers — every committed fixture and harness font — are used unchanged. Because the metrics shortcut must agree, it reads a simple glyph's coordinates (not its outline), so corrupt point data now fails `GetGlyphMetrics` as it fails rendering.
- A `USE_MY_METRICS` composite takes the component's advance as well as its bearing (at an instance, the component's `HVAR` or phantom-point delta), as the spec intends and FreeType does — not its own `hmtx` entry, which Roboto Flex varies differently.
- WOFF2's Brotli stage is a pure managed decoder we write in core (not `System.IO.Compression.BrotliDecoder`, not a third-party package): `BrotliDecoder` wraps the runtime's native Brotli library, which browser-wasm does not ship — it throws `PlatformNotSupportedException` there (dotnet/runtime#91279, open). The API carries no `[UnsupportedOSPlatform("browser")]`, so the analyzer would not catch it. `KernSmith.Fonts.Web` exists to serve browser/WASM, and CSS font CDNs serve WOFF2, so a BCL-Brotli WOFF2 would fail on exactly the platform that needs it.
- Native reads CFF the way FreeType does where the spec leaves room, not spec-literally: the advance comes from `hmtx`, not the charstring width; and the FontMatrix's absolute scale is ignored (normalized to a y scale of 1, so `head.unitsPerEm` sets the em), not applied as `matrix × unitsPerEm`. Swapping backends must not resize or respace an `.otf` atlas, and every other backend and the shared metrics code follow FreeType here.
- Native's hinting code (`Internal/Hinting`, `GlyphHinter`, `GlyphPipeline`, `NativeRasterizer`) uses only arithmetic the IEEE standard pins down — +, −, ×, ÷, `Sqrt`, `Floor`/`Ceiling`/`Truncate`, `Abs`, `Min`/`Max`, and `Round` only with an explicit `MidpointRounding` — never a libm transcendental (`Pow`, `Exp`, `Log*`, trigonometry, `Cbrt`), no width-dependent SIMD reductions and no output that depends on `Dictionary` iteration order, because Native must be byte-identical on the CLI, desktop, MonoGame/KNI, Blazor WASM (interpreter and AOT), NativeAOT, x64 and arm64 (Jeremy's standing rule): slopes are compared as ratios, not angles, and the taper is a clamped linear ramp. `NativeSourceDeterminismTests` enforces the project-wide libm/parallel/SIMD rule; `HintingDeterminismTests` adds the explicit-`MidpointRounding` rule for those sources.
- Native and `KernSmith.Imaging` build without `AllowUnsafeBlocks` (Jeremy approved), not with the flag the other backends carry: neither has `unsafe` code, and without the flag none can creep in unnoticed.
- Native may use parallelism where it helps, but only behind an opt-out option — on by default where supported, forced off on browser-wasm and any other single-threaded target — not banned outright (the original Phase 160 rule) and not mandatory: the browser is a first-class target that has no threads, and a caller must be able to get serial output everywhere. Not implemented yet; Phase 177 measures whether it pays first.
- Native's glyph metrics are judged against the font's own glyph math, with FreeType as the reference approximation, not as the definition of correct: Native matching within ±1 px of FreeType is expected, and any difference beyond that must be explained, validated against the font data and signed off by Jeremy before Phase 179's metrics criterion is ticked.
- Native's default request hints at `HintLevel.Normal` whenever `EnableHinting` is on (Jeremy's choice, 2026-11-01: "if they don't provide it, hinting is a scaled applied thing depending on size"), in every anti-alias mode including `Light` (which no longer selects the y-only fitter by itself), and at `None` with hinting off; an explicit level always wins. The earlier "`Default` hints only `Light` + `EnableHinting`, so default output must not change" rule is gone: Native is not on NuGet, so no shipped output changed, and the goldens and characterization hashes were regenerated deliberately. The size scaling is the hinter's own taper, measured with the hint-parity legibility score at full strength against unhinted on Roboto, Noto Sans and Source Serif: grayscale gains +0.09 to +0.11 at 9 ppem, up to +0.05 at 15-18 ppem, and Source Serif loses 0.04-0.06 from 20 ppem on; so full strength to 16 ppem, the shape-changing x axis (stems into columns, width classes, the by-side placement, the stem-pair padding) gone by 24, and the y axis (zones, baseline, x-height stretch) by 40, both linear and monotone with the x strength never above the y strength (`HintTuning.TaperStartPpem`/`XTaperEndPpem`/`TaperEndPpem`). The bilevel stroke renderer and the color-layer hinting follow the same taper, so output above 40 ppem is byte-identical to unhinted in every mode. `Light` stays y-only by design — the meaning of "Light", as in FreeType's light mode — and moves no point more than one pixel from the unhinted outline (a fit needing more is refused and the edge interpolated): unbounded, those rules stacked hairline curves into one-pixel strokes and captured accents into zones. `Normal` fits x too, the way FreeType's auto-hinter in normal mode does on Roboto (its stems in one column), because the measured gap to FreeType at 12 px was ink concentration — a 0.82 px stem split over two columns — which no y-only fit or darkening can close; it keeps a one-pixel cap per edge at full strength and adds the x-height band stretch. It is Native's own algorithm written from the measured FreeType output, not a port (the code-originality decision). Grayscale strokes under a pixel keep their coverage instead of becoming solid pixels because FreeType's do (overshooting it would over-darken). A color glyph's layers (`COLR` v0 layers, v1 paint graphs and clips) are prepared at `Light` under a `Normal` request while the taper runs, not at Normal: Normal chooses each glyph's stem phase and x placement on its own, and layers fitted one by one no longer register on each other.
- Under `Normal` every advance is the font's, rounded once, in both anti-alias modes, and the fitted ink is placed by side within it — the left bearing at or within 0.25 px above the font's (`HintTuning.LeftBearingSlack`), the fit's slack on the right — rather than rebuilt from the fitted ink (Jeremy's direction: spacing must not be forced into bearings; a line of hinted text is as long as the unhinted one, within ±3% as the bound and 0% as built). Rejected, with their measured cost over a pangram at 8-16 px: FreeType's rule, the fitted right edge plus the font's right bearing, which folds each glyph's sub-pixel stem phase into its advance (Arial's tabular digits at 12 px five at 6 and five at 5, "01234 56789"; Roboto 'i'/'l' at 10 px at 1 px, "ill" one grey block; "nn" 2.3 px apart against 0.35 for "oo"); the linear advance plus the ink's growth clamped to ±1 px, which drifts systematically because bilevel stems all widen and grayscale pitches round down as often as up (bilevel Roboto 8 px +21%, Source Serif 8 px +12%, grayscale Noto Sans 8 px -9%, Roboto 14 px -4%); and whole-column bilevel bearings — both sides rounded up to a column, two columns between lowercase letters as FreeType's mono sets — which made Roboto 12 px bilevel 17-26% longer than the font and every tabular digit cell as roomy as the widest digit's. By side, every pair's gap is the left glyph's slack plus the right one's small shortfall, so the text is even; placing bearings to nearest put stem-sided glyphs' slack on the left and round glyphs' on the right ("q u" 2.3 px apart where "nn" set 1.3). Tabular digits and fixed-pitch faces keep their columns by construction (one font-unit advance rounds to one pixel advance), so there is no digit lock to tune. The pairs that then touch are opened per pair by the kerning bake below, never by padding; a renderer that ignores BMFont kerning gets the touching pairs unhinted text has today. The one exception, and only when the bake is off: a glyph whose right edge is a straight stem (`StemEdges`: straight vertical segments at the extreme x covering 40% of the ink's height) with under a quarter pixel of font white, left under a column of white by the placement, gets a column of advance, so two stems never fuse ("rn" into "m"); nothing else is padded, and nothing is padded on a fixed-pitch face.
- `BakeHintingIntoKerning` is a `bool?` on `FontGeneratorOptions`/`RasterOptions` (null = the backend's choice; `.bmfc` `bakeHintingIntoKerning=1|0` written only when set; CLI `--bake-kerning`/`--no-bake-kerning`), and Native bakes exactly when it hints at `Normal` — which its default is at text sizes — not off by default as first built: with advances the font's and stems on whole pixels a few pairs come out with no white between their inks, and the pair is the only place a per-pair correction can live (Jeremy: pair-level kerning is the mechanism). The bake leans zero-sum rather than correcting every pair's gap (the first version emitted 1000-2500 pairs over ASCII to bring every gap within half a pixel of the font's): it opens only a pair that would otherwise have no column between its inks — in bilevel any such pair, in grayscale only one whose facing columns are both at least three-quarters covered on a shared row (two stems, or a stem and a bar's end; a bowl's fringe or a diagonal's foot against a stem still reads as two letters) — to one column, takes a compensating pixel back from one of the left glyph's pairs that has two or more columns of white (widest first, then by codepoint, so the choice is deterministic) while such pairs last, never touches two digits (tabular columns) or a glyph with no ink (the space), emits only non-zero pairs, and emits nothing for a fixed-pitch face. Roboto at a 12 px cell (9.1 ppem): grayscale 392 pairs over ASCII and 1464 over ASCII + Latin-1, all openings; bilevel 3044 (2996 opened, 48 closed) and 13517, because whole-pixel stems in the font's advances touch in most lowercase pairs at that size (FreeType's mono instead grows the advances). Sides are keyed by the whole request, so one instance rendering two sizes or modes never pairs them. A face is fixed pitch when `post.isFixedPitch` says so or at least 95% of its mapped printable ASCII glyphs share one font-unit advance (`GlyphHinter.IsFixedPitch`), since fonts that forget the flag still set in columns; the `bool` → `bool?` change is accepted as an API change on an unreleased option.
- Native's `Normal` bilevel (`AntiAliasMode.None`) output is a purpose-built stroke renderer (`MonoStrokeRasterizer`: one midpoint pixel per scanline for spans under 1.5 px along the stroke's longer axis, centre sampling elsewhere, connectivity-aware dropout, a 4× counter/aperture check), not the 50% area threshold with dropout control and not a geometric thickening in the hinter: the threshold doubles a sub-1.5 px stroke wherever two pixels each pass 50% (Arial's bowls at 12 px came out two pixels where its stems were one), drops it where none does, and the TrueType dropout rule then re-lights midpoints per row *and* per column, so diagonals step unevenly; thickening in the fitter was tried by the shapes work and made it worse. Legibility is the goal, not FreeType's bits, per Jeremy's direction — `None` and `Light`, and every size past the taper's end, keep the threshold renderer byte-identical. A span under 1/32 px is no span at all: a zero-area contour's two sides cross a scanline a rounding error apart, and the dropout pass must not restore that sliver as a hairline.
- The stroke renderer judges topology against the *fitted* outline sampled at 4×, not the unhinted one: the renderer only has the prepared glyph, and the unhinted shape sits up to a pixel away after the fit, so its counters would map to the wrong pixels. The cost is that an aperture the fitter itself closed (Roboto's 's' and 'G' at 10 px, where the terminal lands on the bowl) looks like a real counter and stays closed — a fitter matter (mono counter minimum), not a renderer one.
- Native's `Gamma` follows the FreeType backend's normalized contract (1.8 = identity, exponent 1.8/gamma on coverage), not a linear-light-to-sRGB conversion: the public option is documented that way, Hiero configs carry 1.8, and a `.bmfc` must render the same tone on either backend.
- Thin-stroke darkening is part of `Normal` grayscale below 9 ppem rather than a new public option: it needs no geometry and changes nothing a current `Normal` test pins (the 12 px cell is 9.1 ppem), and a new `RasterOptions` member would touch core while three sibling branches are open. Jeremy may still move it behind an option.
- Native's `None` output gets dropout control and ink-cropped boxes, not a plain 50% threshold in the outward-rounded box: the plain threshold erased strokes under half a pixel (Roboto's `l`/`I`/`|` at 6-8px) and left empty edge rows and columns that FreeType's mono boxes do not have. `None` metrics therefore render the glyph to measure it (exact cropped boxes); that cost is accepted rather than estimating the box.
- Native does not cache prepared glyphs between `GetGlyphMetrics` and rasterization: core runs `QueryAtlasSize` and `Generate` on separate rasterizer instances, so no instance decodes a glyph twice. Metrics instead skip decoding where the box alone decides them (the header-box shortcut).
- Native's COLR foreground color (palette index 0xFFFF) is opaque black — white only for a palette flagged usable on a dark background — not a caller-configurable color: it is FreeType's documented default, so the two backends color text-colored layers alike.
- Color bitmap PNGs (`CBDT`/`sbix`) are decoded by our own `KernSmith.Imaging` decoder, not StbImageSharp (which core already references): StbImageSharp is a C port on unsafe pointers, and font PNGs are untrusted input. `PngFormatException` derives from `FormatException`, not `BmFontException`, so the assembly stays free of KernSmith dependencies; Native wraps it in `RasterizationException`.
- Native scales a bitmap strike to the requested size (smallest strike at or above it, else the largest; exact area averaging down, bilinear up, in premultiplied sRGB), not FreeType's strike-size output: an atlas must come out at the size asked for. At the strike size the two match. Precedence is `COLR` v1, `COLR` v0, bitmap, outline. Without `ColorFont`, a bitmap-only face draws grayscale ink coverage, alpha × (1 − linear luminance), as FreeType converts color bitmaps to gray; `None` thresholds bitmap alpha at 50% and crops to ink, like Native's `COLR` glyphs.
- Vector outlines are opt-in (`OutlineMode.Vector`, default `Effect`) and drawn by a new default-null `IRasterizer.RasterizeOutlineLayer`, with `SupportsOutlineStroke` redefined as "implements it" (FreeType, which never stroked, now reports false): every backend's default output stays unchanged, and core still owns placement, color, layering and cell sizes, so switching modes never moves a cell or `.fnt` offset. The ring is a distance-based dilation of the prepared glyph, not a union of stroked pieces — filling `OutlineStroker` pieces over-darkened anti-aliased edges where pieces overlap. A face with color glyphs keeps the effect for every glyph under `ColorFont`, so one atlas has one outline look.
- A non-default `WidthPercent` or `ItalicAngle` on a backend without `SupportsWidthScale`/`SupportsItalicAngle` throws `NotSupportedException` rather than rendering at 100% / the backend's own slant: no silent wrong output. Exactly 12° stays FreeType's fixed-point slant, so default italic output is unchanged.
- Native's COLR version 1 renderer interpolates gradients and composites in premultiplied linear light, not sRGB, because the COLR and CPAL chapters require it and FreeType's backend cannot render version 1 to match against. Browsers composite in sRGB, so anti-aliased edges between overlapping colored layers come out lighter than in a browser. Version 0 layers stay sRGB source-over to match FreeType.

## Channels & Compositing

- Per-channel content routing and channel *packing* are two separate mechanisms, deliberately gated differently — conflating them is the easy mistake.
- A non-default `ChannelConfig` is honored **whenever present** (`ShouldApplyChannelConfig` is just `Channels is { IsDefault: false }`), because `ChannelCompositor` natively routes outline/shadow content into individual channels whether or not other effects are active. The narrower 0.15.2 gate — apply only when `fourChnlPacked=1` or the font has no baked effects — no longer exists.
- `ChannelPacking` (grayscale-per-glyph packing via `ChannelPackedAtlasBuilder`) stays mutually exclusive with both effects and color fonts, enforced by hard `InvalidOperationException` guards in `Generate`: effects produce RGBA glyphs and color glyphs are RGBA, neither of which can be packed into a single channel.

## Float Equality

- Exact comparison on floats is kept at every CodeQL-flagged site (not an epsilon), for four distinct reasons. An epsilon would be a bug at most of them, not a fix.
- *Bit-copy*: `MathF.Max` selects one of its arguments rather than computing a new value, so `max == rf` is an identity test; an epsilon could match two near-equal channels and pick the wrong hue sector.
- *Divide-by-zero guard*: `delta == 0` guards `x / delta`, and IEEE gives exactly `0.0` for `x - x`, so a true gray always trips it; an epsilon would flatten faintly-colored pixels to gray.
- *Fast-path skip*: `(1*x)+(0*y)` is exactly `x` and `(t - 0f)/1f` is exactly `t`, so taking the branch or skipping it is output-identical — these cannot produce a wrong answer at all.
- *Default round-trip*: `if (options.SdfSpread != 8f)` asks "did the user change this field", not "is this equal to 8"; an epsilon would silently fail to persist a user-set 8.0001, which is data loss.
- Horizontal-edge rejection (`ScanlineRasterizer.AccumulateEdge`, `OutlineFlattener`'s `EdgeBuffer.Add`, and the along-the-scanline test in `DropoutControl.Reach`) stays exact because the fill relies on signed Δy summing to zero over a closed contour — dropping an epsilon-Δy edge would break closure and produce fill artifacts. `OutlineFlattenerTests` asserts exactly this invariant.
- Pixel line metrics (`lineHeight`, `base`, a backend's ascent/descent) round up through `RasterizerFontMetrics.CeilingToPixels` — a ceiling that treats a value within one part per million of a whole pixel as that pixel — not plain `Math.Ceiling` and not round-to-nearest (#266): with BMFont cell sizing the line box is exactly the requested size in theory, but the float ppem left it a hair above for about half of all sizes, so a plain ceiling wrote `size + 1`; rounding to nearest would clip glyphs when a box is genuinely fractional. The helper is public (not internal) because Native and StbTrueType compute their own metrics in separate assemblies, and `InternalsVisibleTo` across separately shipped packages would tie them to core's internals.
- The genuinely risky shape — comparing two independently-computed values, e.g. `computedAdvance * scale == target` — does not appear in this codebase; that is why the alerts were dismissed individually rather than filtering the rule.
- The rasterizer horizontal-edge sites use `float.Equals` instead of `==` (chosen with Jeremy): `Single.Equals` is defined as bitwise `==` plus NaN==NaN (unreachable at these sites — non-finite edges are dropped by the adjacent `IsFinite` check), so semantics are identical, but `cs/equality-on-floats` only flags the `==`/`!=` operators and stays quiet. GitHub code scanning has no working inline-suppression comment for C#, so restructuring the expression is the only line-level silencer. Do not "simplify" these back to `==`.

## CodeQL Configuration

- Filter by `problem.severity: recommendation`, never by rule id, so nothing CodeQL rates error or warning is ever hidden. Dropping the filter restores the style-suggestion noise that previously buried real findings.
- No `paths-ignore` block in the config (removed in PR #197): it is inert for C# when the workflow builds, and dead config that looks load-bearing is worse than no config.
- Generated-code alerts are removed at the source, not dismissed: no Roslyn source generator whose output trips CodeQL is used in a solution project. The regex generator (`RegexGenerator.g.cs`, `cs/useless-assignment-to-local`) is replaced by runtime `Regex` instances, and the System.Text.Json generator (`cs/useless-cast-to-self`) by hand-written `Utf8JsonWriter` code (`KernSmith.ColdStart`'s `ColdStartReport.ToJson`). Both replacements stay trim/NativeAOT/WASM safe. `CssParser` uses `RegexOptions.NonBacktracking` because CDN CSS is untrusted input and its `url(` pattern backtracks catastrophically on a long whitespace run (20,000 spaces did not finish in 30 s); that engine can split whitespace differently between a lazy group and an adjacent `\s*`, so every captured group is trimmed before use.
- The rasterizer float-equality alerts were resolved in code (`float.Equals`, see Float Equality above) rather than dismissed, so the alert list stays at zero and a *new* float-equality alert is always signal, not known noise.
- If a generator that cannot be replaced ever adds noise, the real lever is the build step in `codeql.yml`, not the config file.

## Regression Harness

- `regression_check.py` builds `GenerateAll` as a separate **fatal** step, because `dotnet run` exits 1 for both a build failure and a partial generation; tolerating both let a non-compiling harness leave stale output in place, so the diff compared main against itself and reported a false pass.
- A backend declining a capability the config requests (SDF on GDI/DirectWrite, MSDF on everything but Native) is a **skip**, not a failure — otherwise adding an SDF config would permanently red the harness.
- `regression_check.py` fails on a (config, backend) pair that produced output on the base but fails on the branch, and tolerates a pair failing on both sides: a both-sides failure is a capability gap, while a branch-only failure is exactly the regression that tolerating every failure used to hide. A config on only one side is reported `NEW`/`REMOVED` without failing, since there is nothing to compare.
- An `sdf.bmfc` config exists specifically because no other config exercised the SDF path, so the harness would report "identical" for SDF changes without ever running them.
