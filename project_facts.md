## Stack & Conventions

- C# / .NET, multi-targeting `net8.0;net10.0`, so building the solution needs both SDKs.
- Projects are deliberately **not** unified on one TFM. `Directory.Build.props` sets the `net8.0;net10.0` default, used by core, `KernSmith.Fonts.Web`, and the FreeType/StbTrueType/Native backends. The exceptions: `Rasterizers.Gdi` is `net8.0-windows;net10.0-windows`; `Rasterizers.DirectWrite.TerraFX` is `net10.0-windows` only; `KernSmith.Cli` adds both `-windows` variants; `KernSmith.Ui` is `net10.0;net10.0-windows`; `Samples.BlazorWasm` is `net10.0` only.
- NuGet package ID and main API class are both `KernSmith`.
- Nullable reference types are enabled.
- Testing is xUnit + Shouldly. `dotnet test` runs in Microsoft.Testing.Platform (MTP) mode — `global.json` sets `"test": {"runner": "Microsoft.Testing.Platform"}` because xunit.v3 4.x dropped VSTest mode on the .NET 10 SDK. Consequences: pass projects as `dotnet test --project <csproj>` (or `--solution`), TRX comes from `--report-xunit-trx [--report-xunit-trx-filename x.trx] --results-directory <dir>` (the VSTest `--logger`/`--blame-hang` flags no longer exist), and MTP writes results to `TestResults/` under the output folder unless `--results-directory` is given.
- Vic's Gum integration packages (`KernSmith.GumCommon`, `KernSmith.MonoGameGum`) are compiled against a specific published KernSmith version (see the nuspec dependency). The `<Version>` in `Directory.Build.props` must be **>=** that version, or the Gum tests in `tests/KernSmith.Tests` fail at runtime with `FileNotFoundException: Could not load ... KernSmith, Version=X` — restore and build do not catch this because the local ProjectReference wins over the package dependency.
- Core library dependencies: StbImageSharp (PNG decoding for `TargetRegion`). Atlas PNGs are written by core's own `PngEncoder` over the BCL `ZLibStream`; StbImageWriteSharp is only a test-project reference, kept as `ReferenceStbPngEncoder`, the encoder's equivalence oracle. FreeTypeSharp belongs to `KernSmith.Rasterizers.FreeType`, not the core library. `KernSmith.Imaging` (our PNG decoder, used by Native) has no dependencies beyond the BCL.
- Core grants `InternalsVisibleTo` to `KernSmith.Tests`, `KernSmith.Cli` and `KernSmith.Benchmarks` (the benchmarks call the internal Brotli decoder directly).
- `AllowUnsafeBlocks` is set in the FreeType, StbTrueType, GDI and DirectWrite backends, the `tests/bmfont-compare/GenerateAll` harness and `tests/KernSmith.Tests` (which calls stb_truetype's pointer API as an oracle) — never in core, Native or `KernSmith.Imaging`.

## Feature State

- Core GPOS kerning (`TtfParser.GposKerningPairs`, what `TtfFontReader` merges over the `kern` table) resolves PairPos the way a shaper does: within a lookup the first matching subtable wins (format 1 by its record, an explicit zero included; format 2 by first-glyph coverage), and every distinct lookup the `kern` features list applies once, values summed — across all scripts' `kern` features, since a BMFont pair has no script. Contextual and chained positioning lookups are not read. A format 2 second glyph that ClassDef2 does not list is in class 0, with or without a codepoint subset (without one: every glyph the cmap maps). `GposPairs` stays the raw non-zero record list that the `GposEquivalenceTests` oracle pins, so without a subset it still leaves those unlisted class-0 glyphs out (the frozen behavior); only `GposKerningPairs` has them.
- `IRasterizer.GetGlyphMetrics` describes the bitmap `RasterizeGlyph` would return, SDF padding included (FreeType, StbTrueType and Native each add it), and its only core caller is `BmFont.QueryAtlasSize` — so `QueryAtlasSizeCore` must not add the padding again. The query runs `PreparedRasterization.Prepare` (so it sizes at generation's cell-height ppem and render scale, and rejects what generation rejects) and sizes each cell with `PreparedRasterization.MeasureGlyph`: metrics at the render size, height stretch, the `SdfScale`/super-sampling downscale (rounded up, before the effects, as generation does), baked outline/shadow margins in output pixels (`IGlyphEffect.Margins`, summed by `GlyphCompositor.Margins`), and blank glyphs' outline cells. It does not model custom glyphs, post-processors, channel-routed effects or cell-height equalization.
- `.bmfc` channel config (`alphaChnl`/`redChnl`/`greenChnl`/`blueChnl`) is parsed by `BmfcConfigReader` into `ChannelConfig` and honored on the CLI/core path (shipped 0.15.2, PR #128).
- The desktop UI carries channel config end-to-end (`EffectsViewModel.Channels` → `GenerationRequest.Channels` → `GenerationService` sets `options.Channels`), and likewise the rasterizer (Native included), anti-alias mode, LCD filter/order, `SdfMode`, `SdfScale`, outline mode, width, italic angle, color palette and variation axes, which survive project save/load. Native-only settings are disabled on other backends, which generate with the defaults instead of throwing. `--ui-rasterizer <backend>` renders the app's own Gum text on that backend. `TESTING-NATIVE.md` is the how-to for trying Native from a source checkout.
- The Native rasterizer renders TrueType (`glyf`) and CFF/CFF2 (`.otf`, CID-keyed included) outlines end to end and is exposed in the CLI (`--rasterizer native`), the desktop UI and the docs as clearly-labeled experimental. Not published to NuGet (`IsPackable=false`, as is `KernSmith.Imaging`, which it references and which must ship with it); publishing is Jeremy's pending release decision (Phase 179). Packing either locally needs `-p:IsPackable=true` and a prerelease version.
- Native anti-aliasing: `Grayscale` is exact-area coverage; `None` is bilevel — a 50% threshold plus dropout control (an inside run along a row or column of pixel centres that lit no pixel lights its midpoint, after the TrueType smart-dropout rule), with each glyph box then cropped to its ink (so a `None` `GetGlyphMetrics` renders the glyph), or at `Normal` the stroke renderer below; `Light` is grayscale coverage and no longer selects a hinter by itself; `Lcd` is below. Say "bilevel" or "AA none" for the rendering mode and "fixed-pitch" for monospaced fonts — "mono" has meant both. `GlyphHinter.EffectiveHintLevel(RasterOptions)` is the one switch from `RasterOptions` to the level that runs: `HintLevel.Default` is `Normal` with `EnableHinting` on (every mode but `Lcd`) and `None` with it off; an explicit `Light` runs the y-only fitter; an explicit `Normal` (advertised; `Full` steps down to it) runs the both-axis `NormalHinter` (`Internal/Hinting/StemFitter.cs` per axis, x on the transposed outline, after `ExtremaSplitter` has put a node on every mid-curve x/y extremum so bowl and arch extrema are edges; `NormalFontMetrics` adds the standard vertical stem and the x-height stretch to Light's zones — the stretch scales only the baseline-to-x-height band and shifts the zones above it, descenders unstretched, so caps and ascenders round from their own size; the y pass takes edges up to a 7° slope so slightly sloped serif tops snap to their zone, the x pass keeps 4°; a face whose reference glyphs have no straight vertical stem, such as Dancing Script, is fitted in y only) within the font's advance — rounded once from `PreparedGlyph.AdvanceWidth`, the fitted ink placed by side (`NormalHinter.PlaceBySide`), the spacing facts (`PreparedGlyph.Spacing`, a `HintSpacing`) kept for the kerning bake. The taper: full strength to `HintTuning.TaperStartPpem` (16), the x axis to nothing at `XTaperEndPpem` (24), the y axis at `TaperEndPpem` (40) — `NormalHinter.Strength` and `XStrength`, both clamped linear ramps, x never above y; `CoverageRenderer.MonoRenderingFor` picks the stroke renderer only while the strength is above 0, and `GlyphHinter.ForColorLayers` prepares `COLR` layers and clips at `Light` under a `Normal` request while it runs (so layers register on each other), else `None`. `GlyphHinter.Applies` and the metrics shortcut both go through the resolver, and distance fields and `Lcd` are never hinted. Bilevel is fitted before the threshold at `Light`; at `Normal` the fitted outline is drawn by `MonoStrokeRasterizer` (`MonoRendering.Strokes`; `None`/`Light` and sizes past the taper keep the threshold renderer byte-identical): thin spans light one midpoint pixel per scanline along the stroke's longer axis, wider spans are centre-sampled, a connectivity-aware dropout pass keeps strokes whole, a span under 1/32 px is ignored, and a 4× counter check (bitmaps up to 20 px tall) reopens closed counters and small closed apertures. `Normal` grayscale below 9 ppem also runs `ThinStrokeDarkening` (isolated partial pixels × up to 1.4). The stroke renderer costs about 4.5× the threshold one per glyph at a 12 px cell (75 µs vs 17 µs); the hinted default allocates about 5 KB of scratch per glyph more than the unhinted pipeline (`NativeAllocationTests` pin the unhinted path). The `Normal` hinter's constants are one internal record, `HintTuning` (defaults = shipped values); the fitters take it as a parameter, `GlyphHinter` passes none and so uses the process-wide `HintTuning.Current`, which only the hint-parity sweep sets (Native has `InternalsVisibleTo` HintParity for that alone). There is no TrueType bytecode interpreter and no CFF hinter (see `project_decisions.md`). Measured with the hint-parity legibility score against unhinted under the shipped taper: Roboto grayscale +0.09 at 9.1 ppem, +0.04 at 15 ppem, 0 from 40 ppem; Source Serif grayscale -0.04 at 20 ppem; bilevel within ±0.04 everywhere and slightly negative on Roboto and Noto Sans at 9-15 ppem. Mean SSIM of the default against unhinted on Roboto letters: 0.79 at 12 ppem, 0.98 at 24, 0.97 at 32, 0.998 at 36, 1.0 from 40. The phase 188 parity bar against FreeType (advances 100%, SSIM 0.98, mono 95% identical) is not met.
- Native distance fields: `Sdf` renders a field computed from the outline that matches FreeType's SDF bytes to within 2 code values (same encoding, padding and boxes), and `SdfMode.Msdf`/`Mtsdf` render RGBA multi-channel fields (Native is the only backend reporting `SupportsMsdf`). With `ColorFont` on, COLR glyphs stay color under SDF (as on FreeType) and MSDF is rejected. Hinting and LCD never apply to a distance field.
- Native color: with `ColorFont`, `COLR` v1 paint graphs (gradients, transforms, composites, variable paints, linear-light compositing) and v0 layers render as straight-alpha RGBA, and `CBDT`/`CBLC` (index formats 1-5, PNG formats 17-19) and `sbix` (`'png '`, `'dupe'`) bitmaps are scaled from the smallest strike at or above the size (else the largest) — area-averaged down, bilinear up, in premultiplied sRGB. Precedence: `COLR` v1, v0, bitmap, outline; glyphs with none render grayscale. Without `ColorFont`, a bitmap-only face (`BitmapOnlyOutlineDecoder`) renders grayscale ink coverage. Bitmap glyphs ignore bold, italic, width, angle, LCD and hinting; `None` thresholds their alpha at 50% and crops to ink. The FreeType backend renders v1 glyphs as plain grayscale coverage (it does not throw), so there is no reference renderer for v1, and it returns `CBDT`/`sbix` glyphs at the strike's own size (it never scales strikes).
- Native `Bold`/`Italic` are outline transforms matched to the FreeType backend (its `max(0.5px, ppem/24)` embolden strength via Native's own control-polygon offset, then its 12° shear), applied to variable instances, to each color layer/glyph clip and before distance-field generation, so Native reports both synthetic-style capabilities and core skips `BoldPostProcessor`/`ItalicPostProcessor` for it.
- Native variable fonts render at the requested instance (`SupportsVariableFonts`), TrueType through `gvar` and CFF2 through charstring `blend`/`vsindex`, with `HVAR` advances and `MVAR` line metrics; color layers and distance fields follow the instance. Blended CFF2 Private DICT hint values stay at their defaults (the auto-hinter measures outlines instead) and `avar` v2 axis mixing is not applied. The library API takes axis values only; the CLI's `--instance` resolves a named instance to its axis values (`ApplyNamedInstance`).
- Native error contract: a malformed table directory or core table is `FontFormatException` at `LoadFont` (so are malformed or empty color bitmap tables on a face with no outlines); malformed glyph, variation or color data (a bitmap glyph's PNG included — `PngFormatException` is wrapped) is `RasterizationException` from `RasterizeGlyph`/`GetGlyphMetrics`/`SetVariationAxes`; a glyph box over 64 ems or a bitmap over 16384 px per side (padding included) is `RasterizationException` (`GlyphLimits`); a `Size` that is not positive and finite, or a negative `Dpi`, is `ArgumentOutOfRangeException` (`Dpi` 0 means 72, as on FreeType), as is a palette index the `CPAL` lacks; a distance field without `ColorFont` on a bitmap-only face is `NotSupportedException`. Axis values clamp to the nearest end; NaN keeps the default. `NativeFuzzTests` holds this over every fixture.
- Native applies `Gamma` to grayscale coverage (`GammaCurve`, `CoverageRenderer`) with the FreeType backend's contract — 1.8 is the identity, otherwise `(c/255)^(1.8/gamma)`, 0 and 255 fixed — and not to mono, LCD, distance fields or color glyphs; default output is byte-identical. WOFF1/WOFF2 work on it only because core decompresses them before any backend sees the bytes.
- Native's atlas pixels and `.fnt` metrics are byte-identical on every runtime, OS and CPU (CLI, UI, MonoGame/KNI, Blazor WASM interpreted or AOT, NativeAOT, x64/arm64, .NET 8/10) — the one thing the backend exists for, and guaranteed only for the pixels and metrics, not the `.png` bytes (core's deflate follows the runtime zlib). What makes it true: Native and `KernSmith.Imaging` use only IEEE-exact operations plus `Internal/DeterministicMath.cs` (`Exp/Log/Pow/Sin/Cos/Tan/Atan/Atan2/Acos` from `+ − × ÷ Sqrt Round Floor CopySign`; a few double ulps of libm, pinned bit-for-bit in `DeterministicMathTests`), never `System.Math`'s libm functions; no parallel loops; SIMD only in `SignedDistanceField.SplatColumns`, per-lane and bit-pinned to its scalar loop. `NativeSourceDeterminismTests` scans both source trees for violations on every run. What CI proves: `DeterminismManifestTests` asserts `tests/KernSmith.Rasterizers.Native.Tests/Determinism/manifest.json` (SHA-256 of normalized `.fnt` + raw pixels for 242 cases: Roboto, NotoSans Latin, SourceSerif4, DancingScript, BungeeColor × 8/12/16/32 px × grayscale/none/light × hint default/none/light/normal, plus Roboto SDF and Bungee color, all ASCII) on windows/ubuntu/macos (arm64) × net8/net10, the `native-determinism-arm64` job (ubuntu-24.04-arm, Native-only classes: no FreeType oracle there) repeats it on Linux arm64, `wasm-publish` runs the published Blazor sample headless (`tests/KernSmith.DeterminismProbe/wasm-check.mjs`, Playwright) and compares case `roboto/32px/grayscale/default`, and `native-determinism-aot` runs a NativeAOT publish of `tests/KernSmith.DeterminismProbe` over a subset (Roboto 32 px, Roboto 12 px grayscale, the SDF and color cases). The matrix, the hash and the sample/probe share linked source (`Determinism/DeterminismHash.cs`, `DeterminismMatrix.cs`), so they cannot disagree on what is hashed. Regenerate the manifest with `KERNSMITH_UPDATE_DETERMINISM=1` (refused when `CI` is set) only after a deliberate output change; a single-platform mismatch is a bug. The hinted entries (`default`/`light`/`normal`) move whenever the auto-hinter changes; the `none` entries are the unhinted control group and move only when the rasterizer itself does.
- A `(int)` cast of a NaN or out-of-range float is the one arithmetic operation where .NET 8 x64 (`int.MinValue`) and arm64 (saturating, which .NET 9+ made universal) differ; every cast in Native is of a finite, bounded value, and new code must keep it so.
- The FreeType backend's color glyphs are premultiplied RGBA (FreeType's BGRA, channel-swapped), but core treats every `Rgba32` glyph as straight alpha, so FreeType's colored edges come out darker; Native's color glyphs are straight.
- Core resolves `AntiAlias` against `SupportedAntiAliasModes` (`AntiAliasNegotiation`, used by `PreparedRasterization.Prepare`, which `QueryAtlasSize` runs too): an unadvertised `Light`/`Lcd` reaches the backend as `Grayscale`, `None` always passes, and the caller's options keep the requested mode. Negotiation never crosses the `None` boundary, which is why `.fnt` `smooth` can keep reading the requested mode.
- `HintLevel` (`Default`, `None`, `Light`, `Normal`, `Full`; `FontGeneratorOptions`/`RasterOptions`, `BmFontBuilder.WithHintLevel`, `.bmfc` `hintLevel=` in the extension block — written only when not `Default`, unknown values read as `Default`; CLI `--hint-level`) is resolved in the same place by `HintLevelNegotiation` against `IRasterizerCapabilities.SupportedHintLevels` (default interface member, empty = only `Default`): an unlisted level steps down `Full` → `Normal` → `Light` → `None` to the first listed one, else `Default`, silently. `Default` keeps every backend's old reading of `EnableHinting` + `AntiAlias`, so existing output is byte-identical. `EnableHinting = false` with a level other than `None`/`Default` is an `ArgumentException` from `Prepare` (the CLI rejects `--no-hinting --hint-level light` as a usage error before generating). Advertised today: FreeType `None` (`FT_LOAD_NO_HINTING`, the `EnableHinting = false` path), `Light` (`FT_LOAD_TARGET_LIGHT`, the auto-hinter's y-only mode with linear advances — also what `AntiAlias = Light` loads at `Default`; `Normal` steps down to it; an explicit `Full` keeps the default target whatever the anti-alias mode; `RasterizeGlyph` and `GetGlyphMetrics` both go through `LightHinted`) and `Full` (`FT_LOAD_DEFAULT`, its hinted output as it always was); DirectWrite `None` (`NATURAL`) and `Light` (`NATURAL_SYMMETRIC`, its hinting-on path); GDI `Full` only (it ignores `EnableHinting` and always runs the bytecode); StbTrueType `None` (it never hints); Native `None`/`Light`. The desktop UI and the Blazor sample do not expose the level yet.
- `FractionalMetrics` (`bool` on `FontGeneratorOptions`/`RasterOptions`, `BmFontBuilder.WithFractionalMetrics`, `.bmfc` `fractionalMetrics=1` in the extension block, CLI `--fractional-metrics`; off by default) writes each character's unrounded advance and left side bearing, and the hinting deltas where known, to `ExtendedMetadata.FractionalMetrics` (`FractionalCharMetrics`: text `kernsmithchar` lines after the `kernsmith` line, XML `<char>` children of `<kernsmith>`, binary block 6 `chars`; `BmFontReader` reads all three, a `kernsmithchar` line without a `kernsmith` line included). Backends report on `RasterizedGlyph.Fractional` (`FractionalGlyphMetrics`, render-size pixels, exact): Native from `PreparedGlyph.AdvanceWidth` and the pre-hint outline it now keeps as `PreparedGlyph.UnhintedOutline` (lsb = control-hull left = the `hmtx` bearing; the lsb delta is tight-bounds left of the fitted outline minus the unhinted one, because the hint stage's extremum nodes tighten the hull without moving ink; the advance delta is the stem-pair padding column or null), FreeType from a second bitmap-less `FT_LOAD_NO_HINTING` load (bold/italic applied) against the rendered slot's 26.6 metrics. Core (`PreparedRasterization.CaptureFractionalMetrics`) reads the field straight after `RasterizeAll` — the height stretch and every effect rebuild glyphs without it — falls back to `FontInfo.DesignMetrics × ppem/upem` for a backend that reports nothing (default instance, no bold or width scale, no deltas), divides by the super-sample level without rounding, adds the integer advance growth of effects and `AdvanceAdjustX` unrounded, and snaps to 1/64 px (`Sixtyfourths`). `lsb` carries no padding, effect margin or SDF spread (it is the ink's edge, not `xoffset`); custom glyphs and atlas variants have no entries; the incremental session accumulates entries per added glyph and keeps a resumed model's. REF-05 documents the field semantics for renderer authors.
- `BakeHintingIntoKerning` (`bool?` on `FontGeneratorOptions`/`RasterOptions`, null = the backend decides; `.bmfc` `bakeHintingIntoKerning=1|0` in the extension block, written only when set; CLI `--bake-kerning`/`--no-bake-kerning`) asks the backend for `IRasterizer.GetKerningAdjustments` (default interface member, null) once per generation after `RasterizeAll` unless it is false, and `BmFontModelBuilder.MergeKerning` (shared with the incremental session) adds each `ScaledKerningAdjustment` (pixels, float) to the font's scaled pair before the one rounding, making a pair where the font has none and dropping what rounds to zero; without adjustments the merge is byte-identical to the old one. Only Native reports adjustments, exactly when `GlyphHinter.BakesKerning` is true (`Applies`, resolves to `Normal`, and the option is not false): `NativeRasterizer.RecordSides` keeps, per rasterized grayscale/bilevel glyph the `Normal` x fit placed, the whole columns of white in its rendered box on each side and the coverage down its first and last columns (`GlyphSides`), and `GetKerningAdjustments` opens the pairs with no column between the inks (bilevel: all; grayscale: only where both facing columns reach 191/255 on a shared row, `GlyphSides.FusesWith`) to one column, compensates with -1 on the left glyph's pairs that have ≥ 2 columns of white, skips two digits and any blank glyph, pairs only sides recorded for the same `RasterOptions` (`GetKerningAdjustments` runs `ValidateSize` first so the Dpi matches), and returns null for a fixed-pitch face. Roboto at a 12 px cell: 392 pairs grayscale and 3044 bilevel over ASCII, 1464 and 13517 with Latin-1. Fixed pitch is `GlyphHinter.IsFixedPitch(post.isFixedPitch, printable-ASCII hmtx advances)` (flag, or ≥ 95% one advance), computed in `LoadFont`; it also turns off the stem-pair padding.
- `SupportsOutlineStroke` means "implements `IRasterizer.RasterizeOutlineLayer`" and gates `OutlineMode.Vector`: Native reports true; FreeType, GDI, DirectWrite and StbTrueType report false and keep core's bitmap `OutlineEffect` (FreeType reported true before but never stroked). Native's layer declines (→ effect) distance fields, blank glyphs and every glyph of a face with color glyphs under `ColorFont`; core rejects `Vector` + SDF. `WidthPercent` and a non-default `ItalicAngle` (with synthetic italic in effect) need `SupportsWidthScale`/`SupportsItalicAngle` (Native only) and are `NotSupportedException` elsewhere.
- Native renders `Lcd` as `Rgba32` (R/G/B = filtered one-third-pixel coverage in panel order, A = max of the three) through `LcdRenderer`, honoring the public `LcdFilter` (`Default` = `Light` = [1,1,1]/3 box, which matches the FreeType backend's LCD output per channel, SSIM 0.98-1.00; `Smooth` = [1,2,3,2,1]/9; `None`) and `LcdSubpixelOrder` (`Rgb`, `Bgr`, `VRgb`, `VBgr`; vertical orders run in a transposed frame). The kernels live in the internal `LcdFilterKernel`. Other backends ignore both options.
- Core never super samples `Lcd`: when the negotiated mode is `Lcd` (and no distance field), `PreparedRasterization.Prepare` renders at the final size and sends `SuperSample = 1` — this applies to the FreeType backend's `Lcd` too; a backend that degraded `Lcd` to grayscale still supersamples.
- The FreeType backend's `Lcd` output is FreeType's raw LCD buffer labelled `Grayscale8`: three bytes per pixel, so `Width` is three times the pixel width, glyphs land 3x wide in the atlas, and `GetGlyphMetrics` disagrees with the bitmap. It never selects an LCD filter.
- WOFF2 decoding is core-only (`Font/Woff2/`, `Font/Brotli/`): `ManagedBrotliDecoder` is our own RFC 7932 decoder, and its 122,784-byte static dictionary ships as the raw-deflate embedded resource `Font/Brotli/BrotliDictionary.bin` (`*.bin` is marked binary in `.gitattributes`). In steady state it takes about 1.5x the BCL native decoder's time (Roboto WOFF2 Brotli stream: ~2.5 ms vs ~1.65 ms; `Woff2DecodeBenchmarks`).
- The StbTrueType backend checks structure before stb_truetype reads anything (`FontStructureValidator`, internal): file/TTC header, directory and the tables stb reads at `LoadFont`, then each glyph's `glyf` tree or charstring once, on first use (cached), all as `FontParsingException` naming the table; a bitmap over 16384 px per side is `RasterizationException`. It mirrors stb's reading, not the spec where they differ (first directory record of a tag wins, the last Unicode `cmap` record is the subtable checked, CFF offsets decoded with stb's DICT integer rules), and its limits are Native's, duplicated because the packages are separate (component depth 64 and total 4096, 65,536 points or path commands, 2^20 charstring operations, coordinates within ±65536, subroutine nesting 10, stack 48). A `cmap` glyph id at or past `numGlyphs` resolves to unmapped. Every face in a Windows 11 `C:\Windows\Fonts` passes except the symbol fonts whose only `cmap` is (3,0) (Symbol, Wingdings, Webdings, Marlett), which stb_truetype's `InitFont` already refused with a bare `Exception`.
- StbTrueType `None` is stb_truetype's coverage thresholded at 128 plus dropout control (`DropoutControl`, internal, a copy of Native's rule — the packages are separate), computed in our wrapper from the glyph's vertices: the outline is flattened as `stbtt_FlattenCurves` flattens it (same subdivision, same 0.35 px flatness, mirrored in managed code because stb's `CRuntime` allocator is internal) so the spans are those of the polygon stb filled. Both paths apply it — `stbtt_GetGlyphBitmap` (plain) and `stbtt_Rasterize` (synthetic bold/italic) — and both then crop the box to its ink (`CropToInk`; stb's box is the outline's extent rounded outward, which left most small glyphs an empty edge row or column), so a `None` `GetGlyphMetrics` renders the glyph to report the cropped box, as Native's does. `Grayscale` keeps stb's box and metrics.
- Symbol fonts (only a Windows (3,0) `cmap`: Wingdings, Webdings, Symbol) map glyphs at U+F020-U+F0FF; core exposes each at that code and at its byte decoded as Windows-1252 (`SymbolEncoding`, public because the backends are separate packages), as BMFont's SYMBOL charset does. The (3,0) subtable is used only without a Unicode one. FreeType selects `FT_ENCODING_MS_SYMBOL`, StbTrueType's structure check relabels the record (3,1) in its private copy (stb reads only Unicode subtables), Native's `CmapTable` and DirectWrite (`IsSymbolFont`) and GDI (`SymbolEncoding.IsSymbolFont`) look the low codes up at U+F0xx.
- Core's font parser bounds hostile input by work, not just by offsets: `GPOS` kerning stops at `TtfParser.MaxGposWork` steps / `MaxGposPairs` pairs (a subtable visit costs 1000 steps; the largest real font, Calibri Light without a subset, spends about a quarter), keeping the pairs read so far in both `GposPairs` and `GposKerningPairs`. Applying each distinct lookup once does not bound the walk: a repeated listing still traverses its subtables to build the raw `GposPairs`, and one class pair still expands to left×right glyphs; `cmap` format 4/12 throw `FontParsingException` once their codes visited exceed the codepoint space; WOFF 1.0 allocates only what its tables fill and rejects a table claiming more than deflate's 1032x expansion. The `.fnt` family name is sanitized in `TtfFontReader.SanitizeName` (no control characters, `"` -> `'`) and default page stems in `BmFontModelBuilder.PageStem`.
- `KernSmith.Fonts.Web` fetches the `.woff2` source of an `@font-face` rule when offered, else the `.woff` (`CssParser`, by `format()` hint, else extension). CDNs key the format on User-Agent: Google Fonts serves TTF to unknown agents and only WOFF2 to modern browsers, so `WebFontSource` sends a Chrome UA, but not when `OperatingSystem.IsBrowser()` — there the header goes into `fetch()`, is not CORS-safelisted, and Firefox's preflight is rejected by Bunny and Google. The disk cache names files `.woff2`/`.woff` from the byte signature.
- The `.woff2` fixtures (`Roboto-Regular`, `NotoSans-Regular-Latin`, `RobotoFlex-Latin`) were made by fontTools from the `.ttf` committed beside each, so tests can compare a decoded WOFF2 with its exact source; `FONT-LICENSES.md` has the commands.
- Core supersamples (except `Lcd`) and height-stretches for every backend, Native included (`PreparedRasterization`): glyphs are requested at `Size × level` with `RasterOptions.SuperSample = 1` (StbTrueType, GDI and DirectWrite would otherwise multiply by the level again), and only the font-metrics/kerning queries carry the level, at the final size — GDI uses it to measure `lineHeight`/`base` at the super-sampled size and round up, as BMFont does. The downscale (`SuperSampleDownscale`) rounds each advance and bearing to the nearest output pixel, halves away from zero (`DownscaleMetric`); BMFont truncates them (see `project_decisions.md`).
- Native renders through a staged internal pipeline (`Internal/Pipeline/`): `IOutlineDecoder` -> `IGlyphTransform` list (width, bold, then italic at `ItalicAngle`; empty for unstyled requests) -> `GlyphBox` -> `GlyphHinter` (the auto-hinter for hinted `Light`, else a pass-through) -> `IGlyphRenderer` dispatch (SDF or MSDF/MTSDF, else `LcdRenderer` for `Lcd`, else coverage; with `ColorFont`, `ColorLayerRenderer` wraps it, sends `COLR` v1 graphs to `PaintGraphRenderer`, draws v0 layers itself, and prepares every layer or clip glyph through the same decoder, CFF included, and transforms; `BitmapGlyphRenderer` draws `CBDT`/`sbix` glyphs; the vector outline layer is `OutlineLayer`, drawn from the fully prepared glyph); the Native README's "Glyph pipeline" section says where each phase plugs in. `GlyphBox` uses the `glyf` header bbox when the decoder declares one and the outline's tight bounds otherwise; a stale header (missing a stored point by more than a unit, and the drawn outline too) is replaced by the points' control box. `GetGlyphMetrics` measures an untransformed, unhinted, default-instance simple `glyf` glyph from that header box without building its outline (it reads the coordinates only for the stale-header check), for renderers whose metrics depend on the box alone (`IBoxMeasuringRenderer`). `TrueTypeOutlineDecoder` places outlines by the TrueType left side bearing phantom point (pp1 = xMin - lsb — matching FreeType; Roboto has 52 glyphs where lsb != xMin), and a `USE_MY_METRICS` composite takes the flagged component's phantom point and advance (with its `HVAR` or phantom-point delta at an instance). `NativeOutputCharacterizationTests` and the golden masters pin Native's exact output.
- A reformatted or subsetted fixture (e.g. a `.woff2` made from a committed font) must come from a font with no OFL Reserved Font Name: OFL counts a format change as a Modified Version, which may not keep the RFN. Adobe's Source fonts reserve "Source"; Noto and Roboto Flex reserve nothing.
- Color-font fixtures: `NotoColorEmoji.ttf` (CBDT/CBLC only, no COLR) in `tests/KernSmith.Tests/Fixtures/`; `Color/BungeeColor-Regular.ttf` (COLR v0, 9 palettes) and `Color/ReemKufiInk-Regular.ttf` (COLR v1 only) in a subfolder, because core `ColorFontTests` uses the first color font directly in `Fixtures/` and expects the emoji font. Reem Kufi Ink's cmap-reachable color glyphs are only its Arabic marks and digits, and its gradients sit on GSUB-only glyphs. There is no committed CFF or variable color fixture; variable COLRv1 tests hand-build tables (`SyntheticColrV1`). `KernSmith.Imaging`'s PNG tests use the full PngSuite in `tests/KernSmith.Tests/Fixtures/PngSuite/` (licence beside it), with StbImageSharp as a test-only oracle.
- The `.otf` fixtures are `SourceSerif4-Regular.otf` (CFF), `SourceCodeVF-Upright.otf` (CFF2 variable; its default instance is ExtraLight) and `NotoSans-Regular-Latin-CFF.otf` (with its `.woff2`). No CID-keyed fixture is committed — Native's CID tests build synthetic CFF tables. `RobotoFlex-Variable.ttf` carries `fvar`/`avar`/`gvar`/`HVAR`/`MVAR` (its `MVAR` varies no line metric); `DancingScript-Variable.ttf` is single-axis with short `gvar` offsets.

## Build & Test Gotchas

- CliTests and `WoffAllBackendsTests` shell out to the real CLI, resolving `tools/KernSmith.Cli/bin/<configuration>/<tfm>/KernSmith.Cli.dll` from their own output path, so they work under any configuration — but they need the solution built first, which is why CI always runs `dotnet build` before `dotnet test`.
- The regression harness exercises the CLI `GenerateAll` path only, not the UI `GenerationService`; verify UI-generation changes separately.
- `GenerateAll` skips a (config, backend) pair when the backend declines a capability the config requests — e.g. SDF on GDI/DirectWrite, MSDF (`sdfMode=msdf|mtsdf`), `widthPercent` or a non-default `italicAngle` on everything but Native. Any other per-pair exception (color on StbTrueType, say) is caught and logged and the run carries on. Because a pair failing on both sides and a `NEW` config both pass `regression_check.py` (CLAUDE.md), a new feature's own test has to assert the backend actually produced output.
- FreeType rounds an unhinted scaled advance in two steps (to 26.6, then to whole pixels) where Native and StbTrueType round once, so some advances differ by 1 px at small sizes (Roboto's digits at 8px: 4.496 px becomes 5 on FreeType, 4 on the others) — not a Native bug.
- `BmFontBuilder.FromConfig` (the harness's path) copies options field by field and still drops `Gamma`, `FillColor*`, `AdvanceAdjustX/Y`, `GradientOffset/Scale/Cyclic`, `ShadowBlurKernelSize/Passes`, `Variants`, `SizeConstraints` and `TargetRegion`, so `.bmfc` configs using them render without them in `GenerateAll` (the CLI maps them itself and is unaffected).
- `dotnet run` exits 1 for **both** a build failure and a partial generation, so the two must be distinguished by building as a separate step.
- A published (trimmed) Blazor app drops every backend assembly nothing references, so `RasterizerFactory` auto-discovery finds no backend there; the app must `RasterizerFactory.Register` each backend it uses.
- `tests/KernSmith.PlatformSmoke` is deliberately **not** in `KernSmith.sln`: its mobile TFMs need the android/ios/maccatalyst workloads, which the normal CI legs don't install. It builds `net10.0;net10.0-android`, adding `net10.0-ios;net10.0-maccatalyst` only on macOS; `-p:SmokeTarget=<tfm>` narrows it to one target. Only `.github/workflows/mobile-smoke.yml` and the `run-*.sh` scripts build it, always in Release (trimming/AOT).
- Building the Android leg locally needs Android SDK platform API 36: `dotnet build tests/KernSmith.PlatformSmoke -t:InstallAndroidDependencies -f net10.0-android -p:SmokeTarget=net10.0-android -p:AndroidSdkDirectory=<sdk>`.
- The bundled FreeType's `FT_Fixed` (C `long`) is pointer-sized even on Windows x64, so FreeType P/Invoke arrays of `FT_Fixed` (e.g. variation coordinates) must be `nint`, not `int` — an `int` array is read in pairs and silently scrambles every value.
- Android RID fallback gotcha: NuGet maps android-x64 -> linux-x64, so FreeTypeSharp's desktop glibc `runtimes/linux-x64/libfreetype.so` overrides the Android `.so` from its `.aar` and x86_64 fails with `DllNotFoundException` (`libm.so.6`). `src/KernSmith.Rasterizers.FreeType/buildTransitive/KernSmith.Rasterizers.FreeType.targets` (packed to `build/` and `buildTransitive/`) removes FreeTypeSharp `NativeCopyLocalItems` on Android; project references must `<Import>` it explicitly. With it, every packaged `libfreetype.so` is 16KB-aligned.
- In `ci.yml` the Native test step is blocking on every OS (no `continue-on-error`); the core and UI steps keep `continue-on-error` on ubuntu for the old shutdown-hang reason, with the trx gate deciding. The recent ubuntu runs pass cleanly, so the exit code and the gate agree.
- Platform verification: Android (API 34 emulator, x86_64 + arm64, Release, `TrimMode=full`) passes StbTrueType, FreeType and Native. Linux arm64 (CI `ubuntu-24.04-arm`) and Mac Catalyst (CI `macos-26`, maccatalyst-arm64, Release, full AOT) pass StbTrueType and Native; FreeType fails on both with no native library. iOS simulator (CI `macos-26`, iOS 26.4, iossimulator-arm64, Release, no JIT) passes StbTrueType (generate + SDF) and Native; FreeType is not built for iOS (link failure, below). A real-iPhone run (Phase 186) is still pending as extra confirmation. `DefaultSystemFontProvider` returns 0 fonts on Android, iOS and Mac Catalyst (no throw). Blazor WASM: the published `samples/KernSmith.Samples.BlazorWasm` (interpreted; this machine lacks the `wasm-tools` workload AOT needs) generates with StbTrueType and Native in headless Chrome — `?backend=native&font=<url>` generates without a click, and the page shows the determinism hash of the result; CI publishes it (AOT) and runs that path headless against the manifest.
- The smoke app also checks Native's WOFF2 (core's managed Brotli and embedded dictionary), CFF, CFF2 variation, COLR v0/v1 and MSDF paths; its `PublishAot=true` win-x64 build has zero trim/AOT warnings and passes them. The mobile results above predate those checks.
- FreeType on iOS: an iOS app that references `KernSmith.Rasterizers.FreeType` fails to **link**, even if FreeType is never used — FreeTypeSharp 3.1.0's static iOS `libfreetype.a` references 20 libpng symbols (FreeType sfnt PNG bitmaps, `Load_SBit_Png`) that nothing provides. Fix needs a libpng for iOS or an upstream FreeTypeSharp change. The smoke app's iOS build drops the FreeType `ProjectReference` and defines `KSMOKE_NO_FREETYPE`.
- Smoke `KSMOKE_EXPECT_FAIL=<backends>`: those backends' failures report `XFAIL` and don't count; a passing `generate` reports `XPASS` and fails the run, so the table can't go stale. CI sets it for FreeType on Linux arm64 and Mac Catalyst (no `continue-on-error`).
- `mobile-smoke.yml` pins the ios/maccatalyst workloads to 26.5.10318 via a rollback file: the newest workload (27.0) requires Xcode 27, which the `macos-26` runners (Xcode 26.x) lack. Bump the pin with the runner image. NativeAOT publish needs a device RID, so there is no simulator AOT leg; full Apple AOT is covered by Mac Catalyst and real devices.
- Local NuGet validation needs `packageSourceMapping` in the consumer `nuget.config`: route the exact IDs being tested (`KernSmith`, `KernSmith.Rasterizers.*`, `KernSmith.Fonts.Web`) to the local feed and `*` to nuget.org — a `KernSmith*` pattern would also capture Vic's `KernSmith.GumCommon`/`KernSmith.MonoGameGum`/`KernSmith.KniGum`, which only exist on nuget.org.

## CodeQL

- The deliberate exact float comparisons (rasterizer horizontal-edge tests and the `OutlineFlattenerTests` assertions that pin them, `OutlineEffect`'s ring-table lookup at whole squared distances, and the UI slider/float-box checks for an already-shown value) use `.Equals`, which `cs/equality-on-floats` does not flag — see Float Equality in `project_decisions.md`. Everything else is fixed or dismissed.
- `paths` / `paths-ignore` do **nothing** for C# here: they apply only when CodeQL analyses *without building*, and `codeql.yml` builds the solution explicitly.
- Code-scanning dismissal comments are capped at **280 characters**; longer ones return HTTP 422, which looks like a generic failure if stderr is swallowed.
- A dismissal comment **cannot be edited in place** ("Alert is already dismissed", HTTP 400) — PATCH `state=open` first, then re-dismiss.
- PR-level CodeQL results live on `refs/pull/N/merge`. `refs/pull/N/head` has **no analyses at all**, so querying it returns a meaningless empty set that reads like a pass.
